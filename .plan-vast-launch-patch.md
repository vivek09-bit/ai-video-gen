# Plan: Patch the Vast.ai launch so a fresh rental can actually narrate

Goal: make `npm run new` succeed on a freshly rented RTX 4090, then remove the version
drift and false failures that make launches flaky. Three blockers, four hardening patches.

Ordered by dependency. Phases 1-3 are the blockers; 4-6 are drift/robustness; 7 verifies.

## Verified facts driving this plan
- `ai4bharat/IndicF5` IS gated ("you have to accept the conditions to access its files").
  Unauthenticated `snapshot_download` / `from_pretrained` fails. HF_TOKEN must reach the instance.
- The LTX checkpoint IS a standard diffusers repo: `model_index.json` has
  `_class_name: "LTXPipeline"`, `_diffusers_version: "0.32.0.dev0"`, components
  `FlowMatchEulerDiscreteScheduler` / `T5EncoderModel` / `T5Tokenizer` /
  `LTXVideoTransformer3DModel` / `AutoencoderKLLTXVideo` (diffusers 0.32.x API).
- `.gitignore` ignores all of `examples/`, so `examples/indicf5/voices/*` is NOT in a fresh
  clone. It already whitelists `public/audio/prompts/indicf5/`, but that dir is empty.
- Nothing sets `INDICF5_VOICES_DIR` on the instance; `vast_server._indicf5_voices_dir()`
  defaults to `examples/indicf5/voices`.
- `create_instance` passes only `--env "-p 8000:8000"`; no `HF_TOKEN`.

## Phase 1 - Provision the HF token onto the instance  (blocks narration)
1. `scripts/vast_manager.py` `VastManager.create_instance`: replace the hardcoded
   `"--env", "-p 8000:8000"` with a composed docker-options string from a new small helper
   (e.g. `container_env_spec()`), so `-p 8000:8000` stays first and `-e HF_TOKEN=<token>` is
   appended when `os.environ.get("HF_TOKEN") or os.environ.get("HUGGINGFACE_API_KEY")` is set.
   Normalise to `HF_TOKEN` on the wire; the repo's `.env` uses `HUGGINGFACE_API_KEY`.
2. `scripts/vast_server.py` `do_GET` (`/health`): add `"hf_token_present": bool`.
3. `scripts/vast_manager.py` `require_gpu`: when `require_tts` and `indicf5_ready is False`
   and `hf_token_present is False`, raise a message naming the gated repo and the env var,
   instead of the generic "import path is unusable".
4. `scripts/new_video.py` `start_vast`: when `audio_model == "indicf5"` and no token is visible
   in `os.environ`, print an explicit warning before renting. Warn, do not abort
   (`--allow-local-fallback` must stay usable).
5. Optional: add `hf_transfer` to deps and `-e HF_HUB_ENABLE_HF_TRANSFER=1`. Skip unless
   cold-start download time matters.

## Phase 2 - Get the IndicF5 reference clips onto the clone  (blocks narration)
1. Verify the clips exist locally: `examples/indicf5/voices/` appears to hold only `.txt`
   transcripts. If `aarav.wav` and friends are missing, regenerate them first
   (`npm run indicf5:setup` / `npm run indicf5`) - the server cannot synthesise without them.
2. Copy each `{stem}.wav` + `{stem}.txt` pair from `examples/indicf5/voices/` to
   `public/audio/prompts/indicf5/` and commit. `.gitignore` already whitelists that path.
3. `scripts/vast_server.py` `_indicf5_voices_dir()`: resolve in order
   `INDICF5_VOICES_DIR` env -> `<repo>/public/audio/prompts/indicf5` (when populated) ->
   `<repo>/examples/indicf5/voices`. A cold clone then works with no extra env var, and the
   dir is writable for the `_prepared_<stem>.wav` normalisation output.
4. Leave `scripts/tts.py`'s local `INDICF5_VOICES_DIR` (`examples/indicf5/voices`) unchanged.
5. Only if binaries must stay out of git (alternative to step 2): in `new_video.py`
   `start_vast`, when `/health` says the reference is missing, `push_file` the clips over SSH
   and re-check. Prefer step 2.

## Phase 3 - Make the rental big enough and reachable  (blocks video/late-stage runs)
1. `scripts/new_video.py` `start_vast`: replace `disk_gb=50` with one tunable
   (`VAST_DISK_GB`, default 100) used for BOTH `find_existing_instance(min_disk=...)` and
   `provision_instance(disk_gb=...)`, so reuse and rent agree.
   Rationale: pytorch image + deps + FLUX bf16 (~34GB) + IndicF5 + LTX will not fit in 50GB.
2. `scripts/vast_manager.py` `search_gpu`: add `direct_port_count>=1` to the structural
   clause in both the tiered query and the last-resort query, because `create_instance`
   always passes `--direct`.
3. Defer fp8 FLUX (`load_flux_pipeline` single-file path) unless disk stays tight.

## Phase 4 - Pin the remote stack to the versions we verified
1. `scripts/vast_manager.py` `SERVER_DEPENDENCIES`: `diffusers>=0.33` -> `diffusers==0.32.2`
   (matches the local venv and the checkpoint's `_diffusers_version`).
   Keep `torchaudio` last - `test_vast_dependency_abi` asserts `packages[:-1] == SERVER_DEPENDENCIES`.
2. Pin `f5_tts` to the same commit as `requirements.txt`
   (`@13f7c4d627cc10111aea8fe9c0039462cacacdc7`) instead of a floating `@main`.
3. `SERVER_DEPENDENCY_PROBE`: add `from diffusers import FluxPipeline, LTXPipeline` so API
   drift fails at boot. Do NOT add `parler_tts` (tests forbid it).
4. This probe change also self-heals existing instances: an instance whose diffusers lacks
   `LTXPipeline` now fails the marker re-check and reinstalls. No marker rename needed.

## Phase 5 - Stop unrelated conditions from failing the launch
1. `scripts/vast_manager.py` `provision_instance`: move `create_instance(...)` inside the
   `try`, so a create-time error (offer consumed, `--direct` unsupported, quota) blacklists
   the host and tries the next offer instead of aborting the whole provisioning.
2. `scripts/new_video.py` `start_vast`: `conflicting_instances()` currently raises on ANY
   non-4090 instance in the account. Downgrade to a warning + `prune` hint; keep the hard
   failure behind an env flag (e.g. `VAST_STRICT_CONFLICTS=1`).

## Phase 6 - Tests and docs
1. `scripts/test_providers.py` `test_vast_gpu_routing`: the assertion
   `create_args[index("--env") + 1] == "-p 8000:8000"` becomes a containment check, plus a
   new assertion that the token flag appears when a token is set.
2. New tests: env spec includes `-e HF_TOKEN=` only when set and always `-p 8000:8000`;
   `_indicf5_voices_dir()` prefers the populated repo path; probe contains `LTXPipeline` and
   still not `parler_tts`; `packages[:-1] == SERVER_DEPENDENCIES` still holds; conflicts only
   warn.
3. `README.md`: document that the instance needs `HF_TOKEN`, where the reference clips live,
   and the new disk default. Reconcile the `.env` variable name.
4. Reconcile `VAST_IMPLEMENTATION_PLAN.md` status (phases 1.3 / 4.1 / 7.x).

## Phase 7 - Verification
1. `npm run test:providers` - offline gate for phases 1/4/5.
2. `python scripts/vast_manager.py search` - offers still returned with the new filter.
3. `python scripts/vast_manager.py hosts --clear`, then
   `python scripts/vast_manager.py create --disk 100`; watch the `onstart.log` tail and
   confirm the prefetch prints no 401/403.
4. `python scripts/vast_manager.py health --url http://<ip>:<port>`: expect
   `indicf5_ready: true`, `hf_token_present: true`.
5. LTX spike (the old Phase 0 gate, still unproven): time one `448x768`, `num_frames=97`,
   `steps=8` clip; record wall time + peak VRAM.
6. `npm run new -- --topic "..." --minutes 1 --vast-instance <id>`: narration arrives via
   `[Vast TTS Batch]`, audio non-silent, instance stopped at the end.

## Decisions
- Token transport: `--env '-e HF_TOKEN=...'` at create time. The onstart starts the server
  before SSH exists, so `.bashrc` injection cannot reach its environment. Trade-off: the
  token shows in `vastai show instances`; rotate if that matters.
- Voices: commit to `public/audio/prompts/indicf5/` (a few hundred KB) rather than uploading
  per launch; `.gitignore` already allows it.
- Pin `diffusers==0.32.2` rather than chase `>=0.33`.
- Disk default 100GB via `VAST_DISK_GB`.
- Excluded: baked Docker image + network volume (plan 7.1/7.2) and the py3.11 IndicF5
  subprocess venv (plan 1.1/1.4). Latency/cost optimisations, not blockers; too risky to
  bundle with a fix that needs live verification.

## Further considerations
1. Disk vs fp8: raise disk to 100GB (cheap, simple) OR add an fp8 FLUX path (code change +
   quality risk). Recommend disk first.
2. Reference clips: confirm they exist before starting Phase 2. If they only exist as
   transcripts, generating them is a prerequisite that may itself need the GPU.
3. Local IndicF5 fallback is unaffected: `prebuild_indicf5_batch` is guarded by
   `not remote_tts_enabled()`, so a remote run never needs the local 3.11 venv.
