# tube2dscript

Turn a written script into a long-form 2D video — **at zero cost per video**.

Nothing here calls a paid API. Narration is synthesised locally by Kokoro, lip sync
by Rhubarb, ambience and sound effects are generated from scratch, and every frame is
drawn by code with Remotion. The only currency is CPU time.

Two formats are supported, sharing one pipeline:

| Format | Visuals | Sounds like |
|---|---|---|
| **Horror narration** | Procedural: fog, silhouettes, flickering light, grain | Khooni Monday / Scary Pumpkin |
| **Character storytelling** | A code-drawn rig with lip sync | faceless-narrator explainers |

```
script.json ──► Kokoro (local TTS) ──► narration WAV + word timings
                        │
                        └──► Rhubarb (local) ──► mouth shapes A–H/X
                                  │
              make_assets.py ──► ambience beds, stingers, grain
                                  │
                    Remotion (local) ──► out/video.mp4
```

## Cost and licensing

Every component is free and commercially usable:

| Component | Licence |
|---|---|
| Kokoro-82M weights and code | **Apache-2.0** |
| misaki (grapheme→phoneme) | **Apache-2.0** |
| Rhubarb Lip Sync | **MIT** (explicitly permits commercial works) |
| Ambience, SFX and grain | generated by this repo, no third-party audio |
| Horror backdrops | drawn in code, no image assets |
| Remotion | free for individuals and companies ≤3 people |

**Migrating from `edge-tts`?** That package calls an undocumented Microsoft consumer
endpoint with a hardcoded client token, a spoofed Edge user agent and a fake browser
origin. It is not a licensed API, Microsoft's terms prohibit automated access and
reverse engineering, and Microsoft has broken it twice. Its own maintainer says it
*"shouldn't be used for commercial reasons"*. Kokoro replaces it with Apache-2.0
weights running on your own machine.

Avoid for monetised work: **XTTS-v2** (CPML, non-commercial), **F5-TTS** (weights
CC-BY-NC), **Higgs Audio v3** (non-commercial), **Wav2Lip** (non-commercial).

> If you are making manhwa or anime recap videos, note that the visuals in those
> videos are usually licensed webtoon panels. That is a copyright question this
> project cannot solve for you — the procedural visuals here exist partly to avoid it.

## Requirements

- **Node.js 18+** (tested on 24)
- **Python** — `setup.ps1` provisions its own 3.12 via `uv`, no admin rights needed
- No FFmpeg install (Remotion bundles its own)
- No GPU — everything runs on CPU

## Quick start

```powershell
npm install
npm run setup     # Python 3.12 + Kokoro + Rhubarb (~800 MB, one time)
npm run assets    # generate grain texture, ambience beds and SFX
npm run voice     # synthesise narration
npm run render    # -> out/video.mp4
npm run studio    # visual editor with live scrubbing
```

`npm run make` chains assets, voice and render. `npm test` checks the phoneme
alignment that word timings depend on.

## One command, topic to finished video

```powershell
npm run new -- --topic "पुरानी हवेली का राज़" --minutes 10
```

That is the whole flow:

```
topic + length
    -> beats.plan()      structure for free, no model involved
    -> narration         written by a model, or left as a brief
    -> scripts/tts.py    Kokoro narration + Rhubarb mouth shapes
    -> remotion render   out/video.mp4
```

Useful flags:

| Flag | Purpose |
|---|---|
| `--topic` / `--minutes` | what and how long (both required) |
| `--dry-run` | print the shot plan and stop |
| `--no-render` | write `script.json` and stop |
| `--narration FILE` | use narration you already have |
| `--voice` / `--speed` | default `hm_omega` at `0.94` |
| `--scene-seconds` | scene length target, default 24 |
| `--shots` | shots per scene, default 2 |
| `--caption-style` | `statement` (default) or `subtitle` |
| `--no-captions` | switch on-screen text off entirely |
| `--characters` | cast a character; **off by default** |
| `--out` | output path, default `out/video.mp4` |

### On-screen text

The narration appears on screen, word-timed from the TTS engine, in one of two
styles:

| Style | Look | Settings |
|---|---|---|
| `statement` (default) | a few large words in the centre of frame | 3 words per cue, 86 px, no panel |
| `subtitle` | a readable band at the bottom | 5 words per cue, 62 px, panel |

Statement style is the default because these videos are narration plus
atmosphere, so the words carry the picture. Legibility over dark, foggy
backdrops comes from a layered shadow rather than a solid panel, which would
flatten the atmosphere.

Tune it in `script.json`:

```json
"captions": {
  "enabled": true,
  "position": "center",
  "wordsPerCue": 3,
  "fontSize": 86,
  "highlight": true,
  "panel": false,
  "outline": 0,
  "maxWidth": 0.8,
  "rise": 30
}
```

`highlight` gives karaoke-style emphasis to the word currently being spoken.
`outline` adds a dark edge for busy backgrounds; `panel` draws a translucent
backdrop. `rise` is how far words travel as they appear.

**Characters are off by default.** The planner casts nobody unless you pass
`--characters`, because on-screen text plus atmosphere is the stronger look for
narration-driven videos. The rig, lip sync and acting system are all still
present and still work if you want them back.

Measured accuracy: a `--minutes 1` request produced a 58.9 s video, **−1.8%** off
target, because the planner derives word counts from the target and the narration
length then determines the timeline.

### Configuring a narration writer

Narration has three sources, tried in order:

1. `--narration FILE` — narration you already have
2. an LLM — any OpenAI-compatible endpoint, via `LLM_BASE_URL`, `LLM_API_KEY`,
   `LLM_MODEL`. A local **Ollama** server is detected automatically at
   `http://localhost:11434/v1` and needs no key, which makes the whole pipeline
   free end to end.
3. a brief — if neither is available, the exact prompt is written to
   `out/narration-todo.txt` for an agent to fill in, and the command stops
   cleanly rather than producing a silent video.

### Why structure is generated by code

This is the single most important design decision, and it is a cost decision.

A hand-written `script.json` costs about **20 tokens per narration word**, and
**87% of that is structure** — shots, effects, sound cues, ids — while only 13% is
the actual prose. So the planner emits the structure, and the model is left with
the one thing it is genuinely better at: writing the story.

Two consequences:

- Cost per minute drops by roughly **9x**, because only the prose is billed.
- Scene count stops mattering for cost, so scenes can be paced for the story
  instead of padded to save tokens.

The planner also guarantees shape: it selects an arc suited to the length, forces
the piece to open on an establishing beat and close on a resolving one, ensures at
least one reveal, and avoids two consecutive shots of the same visual type.

## Performance (measured, not estimated)

Reference machine: **Intel Core 5 120U, 15 W, CPU only, no GPU.**

```
Narration   7.12 s wall for 12.72 s of audio    0.56x realtime (1.8x faster)
            ~17 min to synthesise a 30 min narration
Rendering   5.19 frames/sec
```

Rendering is the bottleneck. Measured projections:

| Video length | Frames @30fps | Render time |
|---|---|---|
| 10 minutes | 18,000 | **1.0 h** |
| 30 minutes | 54,000 | **2.9 h** |
| 60 minutes | 108,000 | **5.8 h** |

These are unattended runs. Fog is drawn with soft multi-stop gradients rather than a
CSS blur filter, which roughly tripled throughput — a large-radius blur on a
full-width layer is the single most expensive thing Chromium does here, and adds
nothing to an already-smooth gradient.

## The horror format

A scene holds a list of **shots**. Each shot is a visual preset plus grading, and
carries a relative `weight` rather than an absolute duration:

```json
{
  "id": "haveli",
  "headline": "पुरानी हवेली",
  "ambience": {"src": "amb_drone", "volume": 0.5},
  "shots": [
    {
      "visual": {"type": "house", "fog": 0.55, "lit": true},
      "weight": 2,
      "effects": {"vignette": 0.82, "grain": 0.42, "dust": 0.25, "zoom": 0.04, "drift": "in"}
    },
    {
      "visual": {"type": "corridor", "flicker": 0.75, "depth": 0.55},
      "weight": 2,
      "effects": {"vignette": 0.88, "grain": 0.48, "exposureFlicker": 0.3, "shake": 0.2},
      "transition": {"type": "crossfade", "seconds": 1.4}
    },
    {
      "visual": {"type": "candle", "glow": 0.95},
      "weight": 1,
      "effects": {"vignette": 0.9, "drift": "none"},
      "transition": {"type": "fade", "seconds": 1.1}
    }
  ],
  "lines": [
    {"character": null, "text": "उस रात मैंने हिम्मत करके दरवाज़ा खोला।"}
  ],
  "soundCues": [
    {"at": 3.2, "sfx": "sfx_riser", "volume": 0.5},
    {"at": 8.6, "sfx": "sfx_stinger", "volume": 0.85}
  ]
}
```

**Weights, not seconds, is the important design choice.** Shots are normalised across
the scene, so narration length stays authoritative: edit the script and the shots
re-tile automatically, and they can never drift out of sync with the audio.

### Visual presets

| Preset | Description | Useful parameters |
|---|---|---|
| `void` | Near-black, creeping darkness | `creep` 0–1, `tint` |
| `forest` | Bare treeline against moonlight | `fog`, `moonlight` |
| `fog` | Fog banks with a distant glow | `density`, `glow`, `seed` |
| `house` | A house, optionally with one lit window | `fog`, `lit`, `moonlight` |
| `corridor` | Perspective corridor with light at the end | `flicker`, `depth` |
| `candle` | Warm guttering light in darkness | `glow` |
| `figure` | A distant standing silhouette | `distance`, `fog`, `glow` |
| `eyes` | Pairs of eyes blinking in the dark | `pairs`, `spread` |
| `rain` | Rain with occasional lightning | `intensity`, `lightning` |
| `grave` | Gravestones on a foggy rise | `fog`, `moonlight` |

Nothing here needs an image file. `seed` on `fog` shifts the bank layout so two fog
shots in one scene do not look identical.

### Shot effects

All values are 0–1 unless noted.

| Effect | What it does |
|---|---|
| `vignette` | Darkened edges, with a slow breathing pulse |
| `grain` | Film grain, stepped at film rate so it reads as grain not static |
| `dust` | Floating motes drifting upward |
| `shake` | Camera jolt — this is what sells a scare beat |
| `flicker` | Light sputters like a failing bulb (used by some presets) |
| `exposureFlicker` | Whole picture dips, as if the bulb cut out |
| `zoom` | Breathing zoom amount, e.g. `0.03` for a subtle push |
| `drift` | `in`, `out`, `left`, `right`, `none` — slow travel over the shot |

### Transitions

| Type | Behaviour |
|---|---|
| `cut` | Hard cut (default) |
| `crossfade` | Incoming shot fades in *on top of* the outgoing one |
| `fade` | Incoming shot fades up from black |

Crossfades work by overlap: the outgoing shot stays fully opaque and the incoming one
fades in above it. Fading the outgoing shot out as well would darken the middle of the
transition, because both layers would be partly transparent at once.

### Ambience and sound cues

`npm run assets` generates five seamless 30-second ambience beds and five one-shot
effects. They are synthesised from scratch with numpy, so there is nothing to license
and the loops have no clicks at the seam.

| Ambience | Use |
|---|---|
| `amb_drone` | Deep breathing drone — the default under any narration |
| `amb_wind` | Hollow wind — outdoors, night, ruins |
| `amb_hum` | Electrical hum — interiors, basements |
| `amb_rain` | Steady rain with sparse droplets |
| `amb_heartbeat` | Slow heartbeat — building tension before a reveal |

| Effect | Use |
|---|---|
| `sfx_stinger` | Dissonant stab — something appears |
| `sfx_impact` | Low thud — a door, a body, a fall |
| `sfx_riser` | Rising sweep — the build before a scare |
| `sfx_whisper` | Breathy voice just out of earshot |
| `sfx_bell` | Distant bell toll — chapter change or ending |

Ambience loops for the whole scene and mixes under the narration. Sound cues are
placed in seconds from the scene start, so you can land a stinger exactly on a beat.

## Hindi narration

Kokoro ships Hindi voices and they work here. Measured:

```
hm_omega   10.78s audio in 7.68s   (rtf 0.71)
hm_psi     10.68s audio in 7.51s   (rtf 0.70)
hf_alpha   10.07s audio in 7.28s   (rtf 0.72)
hf_beta     9.10s audio in 7.11s   (rtf 0.78)
```

`hm_omega` (male) and `hf_alpha` (female) suit horror narration. **Hinglish works
too** — mixed Hindi and English in one line is common in these videos and is handled
without configuration.

Hindi needs no setup beyond `npm run setup`. Note that narration is read as written,
so numbers are spoken in the language you wrote them in — write `बीस साल` rather than
`20 साल` if you want Hindi numerals spoken.

## Word timing and captions

Kokoro returns audio per *segment*, not per word, so timings are derived like this:

1. The narration is split into sentences (handling `।` and `॥` as well as Latin
   punctuation), and each sentence is synthesised separately — so its duration is
   exact from the sample count.
2. That duration is distributed across the sentence's words in proportion to how long
   each pronunciation actually is.

How the per-word weights are obtained is language dependent:

| Language | Method |
|---|---|
| English | misaki tokens carry per-word IPA directly |
| Hindi and others | espeak's space-separated phoneme string is **zipped against the input words** |
| Fallback | syllable counting (`consonants + vowels − viramas` for Devanagari) |

Timing is exact at sentence level and approximate word to word, which is well within
what burned-in captions need. `npm test` verifies the alignment rate and asserts that
weights are positive and finite.

Captions are off by default for horror (a karaoke subtitle track fights the mood), but
the format supports them:

```json
"captions": {"enabled": true, "wordsPerCue": 4, "highlight": true}
```

## Characters (the second format)

A character is defined once and reused forever, which is what makes it consistent. The
rig is vector shapes positioned by transform, so it cannot drift the way generated art
does. Motion — breathing, sway, head bob, blinking, pupil drift, gestures that scale
with mouth openness — is a pure function of the frame number, so renders are
reproducible.

```json
"characters": {
  "maya": {
    "name": "Maya", "voice": "af_heart",
    "hairstyle": "bun", "accessory": "glasses",
    "palette": {"skin": "#f0c49a", "hair": "#2f2a3a", "shirt": "#e0653f", "accent": "#ffd166",
                "skinShade": "#dba87c", "outline": "#232a33"}
  }
}
```

Place with `cast`: `x` (0 left → 1 right), `scale`, and `flip` so two characters can
face each other. Rhubarb's Hanna-Barbera mouth shapes (A–H, X) drive the mouth, and
only the character owning the current line speaks. See `examples/deep-sea.json`.

### Writing scripts as plain text

About 35% cheaper in tokens than JSON, for the narration format:

```
@title The Deep Sea
@voice bm_george
@char maya af_heart bun
@char sam  am_michael short glasses

# Four Thousand Meters Down
! pattern: grid #061321 #153a5c
! cast maya 0.29 0.92 flip
! cast sam 0.71 0.92
sam: At four thousand meters, the pressure would crush a submarine.
maya: And yet something down there is making its own light.
```

```powershell
.venv\Scripts\python.exe scripts\from_txt.py myscript.txt -o script.json
```

Directives: `@title` `@voice` `@speed` `@fps` `@char` · `#` scene · `!` background or
`! cast` · `>` subtext · `*` bullet · `id:` dialogue · `//` comment.

Shots, ambience and sound cues are **JSON-only**, because they carry structured
parameters that do not compress well into a line-oriented format.

## Token economics

Measured on a real generated video (58.9 s, 2 scenes, 126 words) with
`npm run tokens`:

| Who writes what | Tokens | Share |
|---|---|---|
| **The model** — narration + headlines | **181** | 12.5% |
| **Code** — shots, effects, cues, ids | 1,265 | 87.5% |
| **Total `script.json`** | 1,446 | 100% |

The model only ever writes prose and headlines, so the billable figure is the top
row. Everything below it is free.

| Per minute of finished video | Tokens |
|---|---|
| Narration prose | ~140 |
| Headlines (~2.5 scenes × ~10) | ~25 |
| **Model output, total** | **~185** |
| Structure (generated by code) | ~1,290 — free |
| Kokoro narration, Rhubarb, ambience, render | **0** |

**Audio and video cost zero tokens.** No model is involved in either.

For comparison, having an agent write the whole `script.json` costs ~1,745
tokens/min, so generating structure in code is about **9x cheaper** per minute.

### The real bill is context, not output

The script is written once, but an agent re-sends its context every turn, so
input dominates. Rough shapes, with assumptions stated so you can adjust:

| Context | Turns | Input | Output | Total |
|---|---|---|---|---|
| 15k | 3 | 45,000 | ~1,300 | ~46,000 |
| 25k | 5 | 125,000 | ~1,300 | ~126,000 |
| 40k | 8 | 320,000 | ~1,300 | ~321,000 |

Cached input usually bills at a fraction of fresh input, so the real cost sits
well below these totals. The lever that matters most is **turns**, not tokens per
turn.

## Automation notes

- **Never let an agent read `src/generated/project.json`.** It stores a
  `{text, start, end}` object per word — roughly 47 tokens per narration word, so a
  30-minute script would cost ~214k tokens to read. It is generated output.
- **Let code write the structure.** See above; this is the 9x saving.
- **Prefer plain text for narration-only scripts** (2.00 vs 3.07 tokens per word).
- **`npm run voice` caches per line**, so editing one sentence only re-synthesises
  that line. `npm run voice -- --force` re-does everything.
- **`npm run tokens`** prints the measurement above for whatever `script.json`
  currently holds, and warns if the timeline is stale.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `Could not play audio` for a `.wav` under `public/` | The file is missing. Run `npm run assets` (ambience/SFX) or `npm run voice` (narration). |
| `Kokoro produced no audio` | Voice id wrong. Run `npm run voices`. |
| No mouth movement | Rhubarb missing — re-run `npm run setup`. |
| Captions drift from the voice | Stale cache; `npm run voice -- --force`. |
| Devanagari prints as `????` | Console encoding; the scripts set UTF-8 themselves, so this means output was redirected oddly. |
| Render is very slow | Lower `Config.setConcurrency` in `remotion.config.ts`, or reduce `dust`/`grain`/`fog` density. |
| `spacy` or `numpy` build errors | Something is using the system Python 3.14; use the `.venv` one. |
